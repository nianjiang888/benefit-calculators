# 测算样例

以下样例均为引擎真实输出（`scripts/calculator.py` 可复现）。

---

## 样例 1：标准情形（固定收入、单孩）

**输入**：月总收入 12,000 元，固定收入，1 名子女，子女 8 周岁，当地月人均消费支出 3,200 元

```bash
python scripts/calculator.py --income 12000 --children 1 --child-age 8 --local-cost 3200
```

**输出要点**：

| 项目 | 金额 |
|---|---|
| 月抚养费（低值 20%） | 2,400.00 元 |
| 月抚养费（基准 25%） | 3,000.00 元 |
| 月抚养费（高值 30%） | 3,600.00 元 |
| 一次性给付（120 个月）低 / 基准 / 高 | 288,000 / 360,000 / 432,000 元 |

**充足性校验**：参照值 1,600 元，比值 1.88 → **充足**

**这一档最没有争议**：1 名子女、20%~30% 是法条明文区间。

---

## 样例 2：两个孩子（比例上调）

**输入**：月总收入 9,000 元，固定收入，2 名子女，子女 5 周岁，当地月人均消费支出 2,800 元

```bash
python scripts/calculator.py --income 9000 --children 2 --child-age 5 --local-cost 2800
```

**输出要点**：

| 项目 | 金额 |
|---|---|
| 月抚养费（低值 30%） | 2,700.00 元 |
| 月抚养费（基准 35%） | 3,150.00 元 |
| 月抚养费（高值 40%） | 3,600.00 元 |
| 一次性给付（156 个月）低 / 基准 / 高 | 421,200 / 491,400 / 561,600 元 |

**必须告知用户**：30%~40% 是**实务惯例，不是法条明文**。第 49 条只说两孩以上"比例可以适当提高，但一般不得超过月总收入的百分之五十"。

---

## 样例 3：无固定收入 + 临近成年

**输入**：当年总收入 96,000 元（无固定收入），1 名子女，子女 17 周岁，当地月人均消费支出 2,400 元

```bash
python scripts/calculator.py --annual-income 96000 --children 1 --child-age 17 --local-cost 2400
```

**输出要点**：

- 月均收入 = 96,000 ÷ 12 = **8,000.00 元**
- 月抚养费：1,600 / 2,000 / 2,400 元
- 一次性给付（剩余 12 个月）：19,200 / 24,000 / 28,800 元
- 期限提示：**已满 16 周岁，若以劳动收入为主要生活来源并能维持当地一般生活水平，可停止给付**

**实务提醒**：只剩 12 个月的情况下，主张一次性给付意义不大，按月给付更实际。

---

## 样例 4：低收入多孩（贴近法定上限）

**输入**：月总收入 5,000 元，固定收入，3 名子女，子女 3 周岁，当地月人均消费支出 2,600 元

```bash
python scripts/calculator.py --income 5000 --children 3 --child-age 3 --local-cost 2600
```

**输出要点**：

- 比例区间 **40% ~ 50%**（已贴近第 49 条"一般不超 50%"的天花板）
- 月抚养费：2,000 / 2,250 / 2,500 元
- 一次性给付（180 个月）：360,000 / 405,000 / 450,000 元
- 充足性：参照值 1,300 元，比值 1.73 → 充足

**注意这里的张力**：按比例算"够"，但支付方月收入 5,000 元拿出 2,250 元后只剩 2,750 元生活。第 49 条最后一句"有特殊情况的，可以适当提高或者降低上述比例"正是留的这个口子，实务中支付方可以据此主张降低。

---

## 样例 5：触发"明显偏低"预警

**输入**：月总收入 3,000 元，固定收入，1 名子女，子女 10 周岁，当地月人均消费支出 4,000 元

```bash
python scripts/calculator.py --income 3000 --children 1 --child-age 10 --local-cost 4000
```

**输出要点**：

- 月抚养费：600 / 750 / 900 元
- 一次性给付（96 个月）：57,600 / 72,000 / 86,400 元
- **充足性校验：参照值 2,000 元，比值 0.38 → 明显偏低**

引擎给出的提示：

> 测算值 750 元低于「当地月人均消费支出 4,000 元 ÷ 2 = 2,000 元」，可能不足以维持当地实际生活水平，符合请求增加的法定情形
> 依据：婚姻家庭编解释（一）第 58 条第（一）项

**这是本技能最有价值的一档输出**：算出来的 750 元在法律形式上完全合规（3,000 × 25%），但实际可能不够孩子花。校验直接把这层矛盾摆出来，并且告诉用户"不够"本身就是法定的增加理由——而不是让用户拿着一个合规但不敷使用的数字去签协议。
